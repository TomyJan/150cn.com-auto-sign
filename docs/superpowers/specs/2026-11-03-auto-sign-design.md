# 有益网络自动签到设计

## 目标与授权

在 GitHub Actions 中用真实 Chromium 浏览器登录有益网络，发现并提交已有挂机宝的免费延期。用户授权独立完成设计、开发、验证和原子提交，不推送。凭据仅通过环境变量或 GitHub Secrets 提供，不保存到文件或 Git 历史。

## 已验证的网站行为

2026-11-03 实测：站点使用 www 主机名；登录表单为 `#login_form`，用户名字段 `user`、密码字段 `pass`，按钮 `#submit`。登录成功跳转管理中心，出现 `/manager/logout.asp` 链接。服务器列表 `/manager/server/` 中免费延期链接为 `server_free_renew.html?id=...`。免费延期页面是 POST 表单，目标 `server_free_renew_sub.asp`，`#moneyprice` 为 0，按钮值为“服务器延期”。提交后的 `/services/tip.html` 使用 `.layui-layer-content` 展示结果；本次返回“今日已经续费过了！”。

## 实现决定

- 使用 Node.js 24、ES modules、Playwright Chromium、pnpm。以独立功能分支在当前干净检出内实现，保留结果供用户处理。
- 单账号支持。`SITE_USERNAME`、`SITE_PASSWORD` 必填，保留密码原样；`SITE_BASE_URL` 必填且必须为不含用户信息、路径和查询的 HTTPS origin。浏览器模式、超时、随机操作间隔使用可校验的环境参数；提供安全默认值与 `.env.example`。
- 网站路径和 DOM 选择器是站点适配代码；服务器 ID 来自页面，绝不写死。站点 origin 与业务参数来自环境。登录后只访问同源的明确免费延期路径，提交前核实表单目标及金额为零，拒绝付费或非预期表单。
- 每次新建隔离浏览器会话，通过输入和点击执行，不直接调用登录、延期接口。不添加指纹伪造、验证码绕过或无界重试；遇验证或登录失败报错。
- 浏览器默认无头，允许本地有头；使用简短随机操作间隔与中文 locale，不声称浏览器操作可保证不被网站识别。
- 登录通过管理中心地址和退出链接联合确认。续期业务成功、重复签到、站点明确业务拒绝、没有免费续期目标均退出 0。网络故障、HTTP 错误、验证登录失败、结构变化、未知结果、收费表单退出非 0，不能用 catch-all 吞掉。
- 多台免费挂机宝逐一处理；列表中的同一 ID 去重。单台技术故障记录后继续其余目标，最终失败。每个表单最多提交一次，不重试不确定的 POST。
- 日志和 Actions summary 只包含固定状态、数量和脱敏后业务提示。禁止输出整个页面、账号、密码、Cookie、服务器连接信息；不自动上传截图、trace 或 HTML。

## 工作流

- 自动签到：每天 UTC 00:17（Asia/Singapore 08:17）与手动触发；只读仓库权限、10 分钟超时、同账号任务串行。秘密只注入运行步骤，安装阶段不接触账号密码。
- 代码检查：push、pull_request、手动；冻结安装、格式、lint、真实本地 HTTP fixture + Chromium 行为测试、依赖审计、actionlint。测试不需要 Secrets，不访问真实账号。
- 保活：每月 1、15 日使用 `actions: write` 重新启用自动签到和自身，降低公共仓库 60 天无活动停用定时任务的风险，不产生空提交；已被停用时仍需手动启用。
- Dependabot：每周检查 npm 与 GitHub Actions。Actions 固定完整 commit SHA，参照父目录近期项目。
- 无发布或部署产物，因此不增加 release 工作流。

## 验证与交付

先写有行为断言的测试，观察缺失实现导致失败，再实现。浏览器集成测试覆盖错误凭据、业务拒绝成功、零目标、多目标、HTTP 错误、会话过期、未知页面、收费保护及输出脱敏。真实站点验证最终 CLI，记录实际结果。GitHub 托管 runner 只能在用户推送并配置 Secrets 后执行，不能把本地验证称作已在 Actions 运行。
