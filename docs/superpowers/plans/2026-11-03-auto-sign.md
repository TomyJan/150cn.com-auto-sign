# 有益网络自动签到实现计划

> 使用 executing-plans 逐任务执行，保持原子提交。用户已授权独立推进，不再增加设计审批停顿。

**目标：** 使用浏览器在 Actions 登录并尝试免费延期，准确区分业务结果和技术故障。

**架构：** 配置与输出模块负责环境校验及脱敏；站点适配模块负责页面操作；CLI 管理浏览器生命周期。真实 Chromium 配合本地 HTTP fixture 验证整个站点适配流程。

**技术栈：** Node.js 24、Playwright、node:test、pnpm、ESLint、Prettier。

**规格：** `docs/superpowers/specs/2026-11-03-auto-sign-design.md`

## 全局约束

- 凭据仅在运行时注入；不保存真实会话或页面。
- 不推送，不创建付费订单，不重试不确定的提交。
- 登录成功且业务拒绝仍成功；程序异常失败。
- 运行参数由环境/Secrets/Variables 提供；动态发现所有目标。

## 审查重点

1. 登录 200 响应但未认证，不能误报成功：无退出链接、验证页及会话过期测试。
2. 付费表单、外部链接或重复目标：提交保护及请求计数测试。
3. 网络错误或未知提示被吞掉：HTTP 500、未知页面、超时测试。
4. 多台机器中有异常：其余机器仍处理，最终退出失败。
5. 页面/异常包含秘密：日志和 summary 的脱敏测试，不保存页面。
